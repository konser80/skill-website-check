# Website Check

Механику проверяет скрипт, суждение — ты. Скрипт без зависимостей (Node 18+).

## Запуск

```bash
node ~/.claude/skills/website-check/check.mjs https://example.com   # live
node ~/.claude/skills/website-check/check.mjs ~/js/website-foo       # папка
```

Флаги: `--site https://…` (домен для папки без `site` в конфиге), `--pages N` (сколько внутренних страниц из sitemap сравнивать, по умолчанию 5), `--json`.
Exit code: 1 — есть ❌ must.

**Папка.** Для Astro-проекта скрипт проверяет `dist/` (или `dist/client` для SSR). Домен: `--site` → `site` из astro.config → canonical из index.html. Перед проверкой всегда `npm run build`. Если сборку сделать нельзя, скрипт сам пометит ❌, когда dist старше исходников. Передай это пользователю и опирайся на live.

**Если есть и проект, и домен** — прогони оба режима: папка ловит ошибки до деплоя, live — сервер (редиректы, HSTS, сжатие, soft 404) и «задеплоено не то».

## Уровни

| | |
|---|---|
| ❌ must | сломано: сайт не индексируется или превью/иконка битые |
| ⚠️ should | стандарт, который должен быть на каждом сайте |
| 💡 nice | унификация и полировка (например, sitemap именно `/sitemap.xml`) |
| ℹ️ info | факт для решения, не ошибка |

## Что остаётся тебе после скрипта

1. **og:image** — открой картинку (Read) и оцени: читается ли в превью, не обрезан ли текст.
2. **Title/description** — не просто длина, а смысл: уникальны, содержат суть страницы.
3. **llms.txt** — прочитай: актуальны ли факты и ссылки.
4. **AI-боты в robots** — ℹ️; не меняй без явного решения пользователя.
5. **Аналитика/верификация** — если счётчика нет, спроси, нужен ли (скилл `yandex-metrika`).

## Отчёт

Порядок: итоговые цифры по каждому режиму → ❌ → ⚠️ → 💡. ✅ не перечисляй. Каждый ❌/⚠️ — что не так и где чинить (файл в проекте или сервер). 💡 — короткий список, по строке на пункт. Если режимы расходятся (в папке ок, на live нет), назови это отдельно: значит, задеплоено не то или дело в сервере.

## Исправления — только по запросу

По умолчанию только отчёт. Когда просят починить — рецепты в `astro-fixes.md` (robots, единый sitemap.xml, мета в BaseLayout, иконки, llms.txt, JSON-LD, 404, nginx). После правок: build → повторный прогон скрипта по папке → показать, что пункт стал ✅. Live станет зелёным только после деплоя — так и скажи.
Серверные пункты (редиректы www/http, HSTS, gzip) — через скилл `vps-admin`.

После успешной проверки live предложи отправить sitemap в GSC и Вебмастер (скиллы `google-search-console`, `yandex-webmaster`).

## Частые ловушки

- robots.txt указывает на `/sitemap.xml`, а `@astrojs/sitemap` сгенерировал `sitemap-index.xml` → 404 у поисковиков.
- Нет `site` в astro.config → относительные/кривые URL в sitemap, canonical, og:image.
- `public/robots.txt` и `src/pages/robots.txt.ts` одновременно — какой победит, неочевидно.
- `www.` отвечает 200 без редиректа → дубль сайта.
- og:image относительным путём → соцсети не показывают превью.
